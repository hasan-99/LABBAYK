# لَبّيك | LABBAYK

مشروع توصيل وشراء احتياجات يومية عند الطلب، يبدأ في دمشق وريف دمشق. التطبيق مبني كـmonorepo: تطبيق Expo Router مشترك للويب وReact Native، ولوحة إدارة مستقلة بـReact وVite.

## ملفات المشروع

- `MASTER_PLAN.md` — نطاق المنتج، البنية التقنية، الأدوار، تدفقات العمل، الأمان، الحسابات، الاختبارات، مراحل التنفيذ ومعايير الإنجاز.
- `DESIGN.md` — الهوية البصرية، مكونات الواجهة، الشاشات المطلوبة، دعم العربية وRTL ومتطلبات الإنترنت الضعيف.
- `IMPLEMENTATION_STATUS.md` — سجل الإنجاز والتحقق والعوائق.
- `IMPLEMENTATION_ROADMAP.md` — تقسيم التنفيذ إلى مراحل ومعالم قبول.

## ترتيب البدء

1. راجع `DESIGN.md` و`MASTER_PLAN.md` بالكامل قبل كتابة الكود.
2. افحص المستودع والبيئة؛ أنشئ هيكل monorepo فقط إذا كان المجلد لا يحتوي مشروعاً قائماً.
3. نفّذ المراحل M0 إلى M7 بالتتابع، وسجّل النتائج الفعلية في `IMPLEMENTATION_STATUS.md`.
4. لا تعتبر أي وظيفة مكتملة قبل التحقق منها وفق بوابة المرحلة ومعايير الإنجاز في الخطة.

## أوامر التطوير

- `pnpm install`
- `pnpm dev:web` — تطبيق Expo للويب (ومتوافق مع Android/iOS).
- `pnpm dev:admin` — لوحة الإدارة.
- `pnpm build:web` و`pnpm build:admin` — بناء تطبيقي الويب.

عميل Supabase ومفاتيح النشر المحلية مهيأة للمشروع الجديد. العميل والسائق ينشئان حساباً بالبريد وكلمة السر، ويؤكدان البريد برمز مرة واحدة عند التسجيل فقط؛ تسجيل الدخول اللاحق بالبريد وكلمة السر. السائق يحتاج دعوة وموافقة الإدارة، والمدير يدخل ببريده وكلمة السر. Supabase Auth متاح على الخطة المجانية، لكن مرسل البريد الافتراضي محدود لأعضاء الفريق ورسالتين بالساعة؛ قبل تسجيل مستخدمين خارجيين يلزم ربط SMTP. قالب OTP موجود محلياً، ويجب نسخه لإعداد قالب Confirm signup في لوحة المشروع. لا نحتاج SMS أو Twilio لهذا التدفق. راجع `IMPLEMENTATION_STATUS.md` لمعرفة حالة التكامل.

### تسجيل الدخول بالبريد

العميل والسائق ينشئان حساباً بالبريد وكلمة السر، ويؤكدان البريد برمز لمرة واحدة وقت التسجيل. بعد ذلك يكون الدخول المعتاد بالبريد وكلمة السر، مع رابط لاستعادة كلمة السر عند نسيانها. دعوة السائق وموافقة الإدارة مطلوبة قبل استقبال الطلبات، والمدير يستخدم بريده المسجل ودور `super_admin`. لا يوجد دخول عبر SMS أو Twilio. مرسل Supabase الافتراضي للتجارب فقط؛ قبل استقبال تسجيلات من عناوين عامة، أضف خدمة SMTP من `Supabase Dashboard → Authentication → SMTP Settings`، واضبط قالب `Confirm signup` ليعرض `{{ .Token }}`. لا تضع بيانات SMTP السرية في متغيرات الواجهة أو المستودع.

#### خيار مجاني للتجربة

ممكن استخدام Gmail كمرسل SMTP مؤقت بلا شراء دومين: `smtp.gmail.com`، المنفذ `587` مع TLS، واسم المستخدم وعنوان المرسل نفس حساب Gmail. يلزم تفعيل التحقق بخطوتين وإنشاء **App Password** من إعدادات Google؛ ضعها مباشرة في إعدادات SMTP داخل Supabase فقط، ولا ترسلها في المحادثة أو تحفظها بالمشروع. [Google يتطلب التحقق بخطوتين لكلمات مرور التطبيقات](https://support.google.com/accounts/answer/185833?hl=en)، ويذكر حد إرسال يصل إلى 500 رسالة يومياً للحسابات الشخصية [في صفحة حدود Gmail](https://support.google.com/mail/answer/22839?hl=en). Supabase يضع حداً مبدئياً قدره 30 رسالة بالساعة بعد تفعيل SMTP، ويمكن تعديل حد Auth عند الحاجة [بحسب توثيق SMTP](https://supabase.com/docs/guides/auth/auth-smtp). هذا مناسب لاختبار محدود، وليس إعداد إرسال إنتاجي مضمون.

لأن مشروع Supabase هذا أُنشئ بعد 3 حزيران 2026 على الخطة المجانية، خدمة الإرسال الافتراضية لا تسمح بتعديل قوالب البريد؛ ربط SMTP مخصص مطلوب لاستخدام قالب OTP ذي الرمز `{{ .Token }}` [بحسب إعلان Supabase](https://supabase.com/changelog/46599-changes-to-email-template-customisation-on-free-tier). إعداد SMTP والقالب المستضاف لم يُنفذا بعد.

ملاحظة أمنية: تحذير Supabase Security Advisor الحالي يخص حماية كلمات المرور المسرّبة. هذه الخاصية تتوفر على خطة Pro وما فوق، وليست إعداداً يمكن تفعيله ضمن الخطة المجانية [بحسب توثيق Supabase](https://supabase.com/docs/guides/auth/password-security). لن نطلب ترقية مدفوعة لهذا المشروع دون قرار منك.
